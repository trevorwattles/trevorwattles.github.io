#### What I built

- Rebuilt the payouts workflow: a detail page for each payout run showing every rep, a per-deal breakdown of how each commission was calculated, and a redesigned manual-payout form.
- Built the admin side of the gamification system: badge tiers, badge duplication, badge detail pages linked to goals, and scoring-model management.
- Standardized filtering and list-and-detail layouts across 10+ modules, including Orders, Leads, Quotes, Goals, Teams and Disputes, with filter options matched to the backend's database values.
- Fixed bugs and wrote tests in the Laravel backend: team-hierarchy nesting, role syncing (with regression tests), and permission updates that previously failed with errors.

#### The hard part

Payouts reach the system three ways: generated by a commission run, entered as a named manual batch, or created one at a time. The Payouts table grouped them into one row per pay period, but that logic lived inside the page. So "View Full Details" couldn't reliably find the same set of payouts, and it landed on the wrong page or sent a query the backend couldn't filter. I moved the grouping rules into a single shared key (run ID, then batch name, then creation time) used by both the table and a new run detail page. Totals and statuses now always match.
